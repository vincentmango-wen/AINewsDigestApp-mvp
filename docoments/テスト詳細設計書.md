# テスト詳細設計書

## 1. ドキュメント概要
| 項目 | 内容 |
|---|---|
| 文書名 | テスト詳細設計書 |
| 対象システム | FocusDigest |
| ベース資料 | `docoments/テスト仕様書.md` |
| 作成目的 | テスト仕様書に定義したテストケースを、第三者がそのまま実行できる粒度まで具体化する |
| 対象範囲 | ニュース取得、記事保存、記事選定、AI要約、メール本文生成、メール送信、定期実行、手動実行API、ヘルスチェックAPI、最新実行結果取得API、ログ出力、設定値検証 |
| 対象外 | Web UI、認証画面、複数ユーザー管理、クラウド運用試験 |

## 2. 参照資料一覧
| No | 資料名 | 用途 |
|---|---|---|
| 1 | `docoments/要件定義.md` | 完成条件、対象外、異常時方針の確認 |
| 2 | `docoments/基本設計書.md` | 処理フロー、再実行方針、ログ方針の確認 |
| 3 | `docoments/詳細設計書.md` | モジュール責務、機能仕様、例外仕様の確認 |
| 4 | `docoments/API仕様書.md` | APIレスポンス、HTTPステータス、エラーコードの確認 |
| 5 | `docoments/データベース設計書.md` | テーブル、制約、状態値、整合性確認 |
| 6 | `docoments/テスト仕様書.md` | テスト対象、観点、ケース一覧の確認 |

## 3. 前提条件
| No | 項目 | 内容 |
|---|---|---|
| 1 | 実行環境 | ローカル環境またはDocker環境でアプリを起動できること |
| 2 | DB | SQLiteファイル `data/app.db` を参照できること |
| 3 | ログ | ログファイル `logs/app.log` を参照できること |
| 4 | API | FastAPIアプリが起動し、対象APIへアクセスできること |
| 5 | 外部連携 | NewsAPI、OpenAI API、SMTPは本番接続またはモック接続のいずれかを準備すること |
| 6 | 設定値 | `.env` または環境変数で必要設定を切り替えられること |
| 7 | データ初期化 | `data/app.db` と `logs/app.log` を試験ごとに初期化または退避できること |
| 8 | 時刻確認 | 定期実行試験ではジョブ登録状態を確認できること |

## 7. 確認方法
| 区分 | 確認方法 |
|---|---|
| API結果 | HTTPステータス、JSONレスポンスボディを確認する |
| DB結果 | `articles`、`digest_runs` をSELECTして状態を確認する |
| ログ結果 | `logs/app.log` を確認する |
| メール送信 | SMTPモック、テスト用受信箱、または送信結果ログを確認する |
| スケジューラ | ジョブ登録状態、起動ログ、実行履歴を確認する |

## 8. 推奨確認SQL

```sql
SELECT id, url, title, category, summary_status, last_sent_run_id
FROM articles
ORDER BY published_at DESC;
```

```sql
SELECT id, triggered_by, started_at, finished_at, fetched_count, selected_count, summarized_count, email_status, error_message
FROM digest_runs
ORDER BY started_at DESC;
```

```sql
SELECT COUNT(*) AS article_count FROM articles;
```

```sql
SELECT COUNT(*) AS latest_run_count
FROM digest_runs;
```

## 9. テスト実施手順共通ルール
| No | ルール | 内容 |
|---|---|---|
| 1 | 事前初期化 | 試験開始前に `data/app.db` と `logs/app.log` を初期状態へ戻す |
| 2 | API起動確認 | API試験前にヘルスチェックで起動確認する |
| 3 | 設定切替 | 異常系は対象設定値のみ変更し、他の設定は正常値を維持する |
| 4 | 1試験1目的 | 同時に複数要因を変えず、試験観点ごとに単独で実施する |
| 5 | 証跡取得 | APIレスポンス、DB結果、ログ結果を試験証跡として保管する |
| 6 | 後片付け | 試験終了後にDBとログを初期化または退避する |

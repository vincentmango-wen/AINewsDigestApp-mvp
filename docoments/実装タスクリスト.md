# 実装タスクリスト

## 1. 目的
- FocusDigestのMVPを、設計資料に沿って破綻なく実装する
- 実装順序、依存関係、完了条件を明確にし、1名開発でも進捗管理できる状態にする
- 対象はMVP必須機能に限定し、Web UI、認証、クラウド本番運用、監視基盤、CI/CDは含めない

## 2. 実装方針
- 実装単位は `設定`、`DB`、`外部連携`、`業務ロジック`、`API`、`スケジューラ`、`テスト` の順で進める
- 単一アプリケーション構成を守り、FastAPI + APScheduler + SQLite + SMTP + NewsAPI + OpenAI API に固定する
- 先に「動く最小縦切り」を作り、その後に異常系、ログ、再現性、テストを固める
- 各タスクは完了条件を満たした時点で完了とする

## 3. 全体マイルストーン

| No | マイルストーン | 完了条件 |
|---|---|---|
| 1 | 開発基盤準備完了 | アプリが起動し、設定読込とロガー初期化が通る |
| 2 | DB基盤完了 | SQLiteで `articles` と `digest_runs` が作成される |
| 3 | 外部連携基盤完了 | NewsAPI、OpenAI API、SMTPの接続処理が単体で確認できる |
| 4 | ダイジェスト処理完了 | 取得、保存、選定、要約、送信が一連で実行できる |
| 5 | API完了 | `health`、手動実行、最新実行結果取得APIが動作する |
| 6 | 定期実行完了 | APSchedulerで毎日08:00ジョブが登録される |
| 7 | MVP完成 | Docker起動、手動実行、ログ確認、異常系確認まで通る |

## 7. MVP完成判定チェックリスト
- [ ] 指定分野のニュースを1回の実行で取得できる
- [ ] 取得記事をSQLiteへ保存できる
- [ ] URL重複を防げる
- [ ] 保存済み記事から上位5件を選定できる
- [ ] 各記事の日本語要約を生成できる
- [ ] 要約成功記事をメール送信できる
- [ ] 全件要約失敗時に `email_status=skipped` になる
- [ ] SMTP失敗時にエラーと実行履歴を記録できる
- [ ] `GET /api/v1/health` が200を返す
- [ ] `POST /api/v1/jobs/digest/run` が手動実行できる
- [ ] `GET /api/v1/jobs/digest/runs/latest` が最新実行結果を返す
- [ ] APSchedulerで毎日08:00ジョブが登録される
- [ ] 成功時と失敗時のログを確認できる
- [ ] Docker環境で同じ動作を再現できる

## 8. 実装時の注意事項
- MVP対象外の機能を混ぜない
- 分野指定は実行時入力ではなく、設定値1件を使用する
- 認証を追加しない
- クラウド前提の構成へ広げない
- SQLite前提を崩さない
- ログ、実行履歴、APIレスポンス形式を途中で独自変更しない

## 10. 最終推奨
- 実装は `DigestService` を中心に縦に通す
- 先に「手動実行で最後まで流れる」状態を作る
- その後にスケジューラ、Docker、テストを固める
- 追加機能ではなく、MVP完成条件の充足を最優先に進める
